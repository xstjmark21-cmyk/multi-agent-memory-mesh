# 跨 Agent 纠错记录（示例）

- **日期**：2026-08-28
- **类型**：事实纠错 / Cross-validation
- **涉及 Agent**：`agent-a`（云端）、`agent-b`（笔记本）
- **裁决人**：用户

## 事件

`agent-a` 在自己的记忆档中记录了某台媒体服务器的局域网访问地址。
`agent-b` 在读取共享中心时，发现该地址与自己在本机实测得到的地址不一致，主动提出质疑并给出实测值。

## 处理

1. `agent-b` 在 `coordination/` 建立本记录，列出两个版本的地址及各自来源
2. 用户确认 `agent-b` 的实测值为正确值
3. `agent-a` 修正本地记忆，`confidence` 置为 `verified`，`verified_by` 加入 `agent-b`，并 `supersedes` 旧条目
4. `agent-a` 立即执行一次手动同步，推送修正结果

## 结论与启示

- **一个助手的记忆错误，被另一个助手抓到了。** 这是共享记忆机制最大的意外收益：多来源记忆天然形成交叉校验。
- 因此记忆条目必须带 `confidence`（已验证 / 声称 / 猜测）与 `verified_by`，让"被多个 agent 确认过的事实"权重更高。
- 涉及可实测的技术事实（地址、端口、版本号）时，**实测方的记录优先于转述方**。

---

*模板用法：每次出现跨 agent 分歧时新建 `coordination/<日期>-<主题>.md`，按「事件 / 处理 / 结论」三段式记录。*
